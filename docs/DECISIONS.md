# Решения

10 октября 2026. Backend: C# / ASP.NET Core 8; frontend: React, TypeScript, SCSS, Vite. Java и Go в презентации перечислены как альтернативы backend; дополнительные сервисы не требуются.

Для запуска без Docker выбран SQLite WAL (реальная файловая БД). Вся операция ресторана выполняется в BEGIN IMMEDIATE: блокировка записи берётся до проверки остатков, включая параллельные процессы. Сущности разделены по таблицам, decimal сохранён в JSON без потери точности. Миграция v1 выполняется при старте. Идентификаторы индексированы PRIMARY KEY. Для небольшого ресторана агрегат читается целиком; это сознательное ограничение масштабирования. Переход на PostgreSQL и выборочные SQL-запросы нужен перед большой нагрузкой.

Единицы: g/ml/pcs; kg/l конвертируются точно. Положительные decimal до трёх знаков после запятой. UTC в хранении, Europe/Moscow по умолчанию. Дата без времени означает начало следующего местного дня (исключительная граница). now >= expiresAt исключает партию немедленно; монитор статусов запускается каждую секунду; списание выполняет менеджер.

Пустая рецептура отклоняется. Рецепт нельзя менять после продаж этого блюда: иначе исторический спрос изменился бы задним числом. Повтор поставки и заказа защищён ключом и хешем содержимого, включая отклонённые заказы. Outbox — долговечная таблица событий; SSE читает её после commit, передаёт revision и заставляет клиента обновить снимок при подключении.

Настройки горизонтов и timezone доступны через API и интерфейс. Прогноз использует равномерный спрос принятых заказов за окно; события истечения учитываются точно. Принятые заказы могут занижать спрос при дефиците. Без истории показываем неизвестный спрос, но известную границу истечения. План горячих предложений использует один виртуальный склад и лимит 100 порций на рекомендацию.

Запись и чтение требуют cookie-сессии или bearer API-ключа. Раздельные аккаунты и роли; первый manager создаётся из bootstrap-пароля окружения. SameSite=Strict, HttpOnly; production требует HTTPS. Запись требует X-Requested-With: Flagman и проверку Origin. Login ограничен по IP. Демо-смещение времени и генератор доступны только с FLAGMAN_DEMO=true; production не меняет часы.

Дизайн: операционный интерфейс на русском, тёмно-зелёная навигация, светлая рабочая область, оранжевые предупреждения. Цвет сопровождается текстом, навигация адаптируется к мобильному экрану, формы доступны с клавиатуры.

## 2026-10-15: граница внешних операций

Внешние заявки отделены от складских проводок. ProcurementRequest/DeliveryRequest/OrderRequest сохраняют авторство, строки, финальные решения и версии. Inventory.Deliver/PlaceOrder остаются внутренним механизмом; публичные старые маршруты создают pending, прямой обход приёмки закрыт. BEGIN IMMEDIATE сериализует финализацию и FEFO между процессами; scope ключа включает actorId и операцию.

Истечение меняет доступность/уведомления, сохраняя physical stock. Ручное полное списание просроченной партии требует manager, actor/reason/audit и ключ. Исторические expiry не восстанавливаются. Предложения имеют независимые visibility/accent; роли получают отдельные проекции. Первая версия исключает резервирование, замены и дробные отгрузки одной закупки. Workflow-команды используют полную загрузку State внутри транзакции: простота и атомарность ценой более дорогого чтения больших журналов; локальная нагрузка измеряется отдельно.
