## Измеренный профиль пилота

Windows 10.0.26300, i7-9750H 2.60 GHz, 12 логических CPU, 16 GiB. SDK 8.0.425 / ASP.NET Core 8.0.31, Node 24.14.0, Playwright 1.64.0. Синтетическая история: 10 000 партий, из них 1 000 активных; 100 000 исторических движений. Одновременно 10 SSE-клиентов, один оператор записи и последовательные чтения. 50 новых заказов, 21 snapshot, 510 доставленных SSE-событий.

| Метрика | p95 |
|---|---|
| Snapshot | 182 мс |
| Заказ | 729 мс |
| SSE | 1430 мс |

Ошибок нет; остаток и exact movement reconciliation проверены. Предварительные цели ≤1 с для чтения/записи и ≤3 с для SSE пройдены **только для этого профиля**. Пилот ограничен одним оператором записи и 1 000 активных партий. Цель пяти конкурентных операторов не пройдена устойчиво: отдельные прогоны проходили, другие давали 2,3–4,8 с p95 заказа. Даже при 1 000 активных партий и пяти операторах были превышения. Неуспешные отчёты сохранены, например `release-20261010-154806-6a65ca` и `release-20261010-155159-2c3ab4`.

Оптимизации: SQL выборки вместо полного агрегата для API, индексы, достаточный FEFO-набор с точной decimal-проверкой и fallback, delta save, асинхронная очередь записей одного процесса. BEGIN IMMEDIATE продолжает защищать конкуренцию процессов. Эксперимент с отдельным checkpoint не устранил паузы и отменён; synchronous=FULL и стандартный checkpoint сохранены. Перед увеличением нагрузки профилировать fsync/очередь на целевом хосте, повторить матрицу с `-Operators 5`.

## Граница приёмки

Это проверенный локально кандидат ограниченного пилота. Docker CLI, целевой Docker-хост, DNS/TLS, права volume, контейнерный рестарт/restore/rollback не проверены. CI подготовлен, но remote и запуск workflow отсутствуют. Внешний мониторинг и расписание backup должен включить администратор хоста. Финальный production-релиз не принят. План контейнерной приёмки: RUNBOOK; статусы каждого P-ID: PRODUCT_TASKS.

Версия/условия находятся в release.json внутри пакета, SHA256 — рядом с архивом. Архив содержит приложение, Maintenance, скрипты backup/restore и инструкции; рабочие БД, пароли и Data Protection keys не входят.

Фактический пакет: `output/flagman-1.1.0-rc1-20261010-160021.zip` (34 599 089 байт, 127 записей). SHA256: `0DE895AF5E271A324514DD6F65A0C2F6C002A9152D416A293426586B07002DB5`. Содержимое ZIP проверено на отсутствие БД, key XML и .env; checksum совпадает. Backup запущен из bundled scripts/Maintenance на отдельной тестовой базе, integrity/reconciliation успешны. Документы внутри ZIP отражают состояние до вычисления его checksum; эта запись — итоговое внешнее свидетельство.
