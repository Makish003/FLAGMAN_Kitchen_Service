# Проверка анимаций «Флагман»

Дата: 10 октября 2026 года, Europe/Moscow. Реализация выполнена по `ANIMATION_IMPLEMENTATION_PLAN.md`, без новых зависимостей и изменений API.

## Реализация и точки внедрения

Исходный checkout `e248cd2` был чистым. Прочитаны README, DESIGN.md, план, сценарии запуска и существующие E2E. Применимых AGENTS.md в проекте и родительских каталогах не обнаружено.

| Компонент | Запрос закрытия | Владелец присутствия / размонтирование | Фокус |
|---|---|---|---|
| OperationModal | Кнопки, клик по backdrop, cancel/Escape, успешная операция | `useDialog` → `usePresence`; App удаляет форму только по итоговому onClose | Нативный dialog и сохранённый инициатор; резервная цель — видимая кнопка меню или main |
| DetailsDialog в App и StockView | Кнопка, cancel/Escape | Тот же useDialog; ключ сущности отделяет экземпляры; загрузка истории сохраняет AbortController | Возврат к инициатору или доступной резервной цели |
| Мобильная навигация | Escape, подложка, кнопка, выбор раздела, открытие настроек | App/usePresence панели и подложки; inert workspace и overflow удерживаются до выхода панели | Цикл Tab сохраняется; завершение меню не забирает фокус из открытого dialog |
| Toast | 6500 мс, кнопка, новое notify | App сохраняет последний текст; usePresence удерживает уходящее сообщение | Кнопка закрытия отключена в хвосте выхода; одна область role=status |
| Combobox | Выбор, Escape, Tab, blur, outside pointerdown | Логическое expanded меняется сразу; хвост списка удерживается usePresence | aria-expanded/activedescendant отражают логическое состояние; закрывающийся список inert и aria-hidden |
| Раздел | page, включая popstate | Одна `.section-motion` с key=page внутри main | App, SSE и общие диалоги сохраняют экземпляры при обновлении snapshot |

`usePresence` различает entering/open/exiting/closed и желаемое открытие. Завершение слушает только собственный animationend с соответствующим animationName, исключая детей и pseudo-element. Резервный таймер равен вычисленной длительности/задержке CSS плюс 50 мс. Таймеры и слушатели очищаются при смене состояния и размонтировании. Reduced motion, отсутствие эффекта и переход на desktop завершают присутствие без ожидания события. Прерванное движение продолжает opacity/transform из текущего вычисленного состояния; чтение стилей выполняется на границе состояния, не на каждом кадре.

`useDialog` — единственный владелец showModal/close. cancel всегда вызывает preventDefault. Во время выхода сохраняются top layer и backdrop. Busy блокирует закрытие; отправка дополнительно защищена синхронным ref. Успешный результат передаётся в App сразу, одновременно запускаются notify и refresh. Отказ заказа остаётся в форме и не допускает повторного submit. Смена сессии снимает меню/блокировки и удаляет диалоги. StrictMode cleanup не возвращает фокус из нового dialog.

## Итоговая матрица эффектов

Токены находятся в `frontend/src/tokens/theme.json`; CSS сгенерирован штатным `tools/design/build-tokens.mjs`. После корректировки темпа fast=170 мс; spin=1600 мс сохранён.

| Элемент | Эффект | Вход / отклик | Выход |
|---|---|---:|---:|
| Кнопки | Цвет; сдвиг 1px только у `.button`, без движения строк таблицы | 170 мс | 170 мс |
| Поля | Цвет рамки и фона; независимый focus-visible | 170 мс | 170 мс |
| Combobox | Opacity, Y=4px; поворот стрелки | 175 мс | 140 мс |
| Все операции и история | Opacity, Y=8px, без масштабирования текста | 250 мс | 175 мс |
| Dialog backdrop | Opacity; статическое затемнение, без blur | 225 мс | 175 мс |
| Меню / подложка | X панели; opacity подложки | 275 мс | 200 мс |
| Toast | Opacity, Y=8px; позиционирование в отдельной оболочке | 225 мс | 175 мс |
| Раздел | Один контейнер, opacity/Y=4px | 200 мс | Новый раздел показывается сразу |
| Компактные индикаторы | Цвет; значения и статусы обновляются сразу | 170 мс | — |
| Spinner | Существующее вращение только во время загрузки | 1600 мс / цикл | Останавливается сразу |

Easing: вход `cubic-bezier(0.16,1,0.3,1)`, выход `cubic-bezier(0.4,0,1,1)`, микроотклик `cubic-bezier(0.2,0,0,1)`. Hover ограничен `(hover:hover) and (pointer:fine)`. Нет transition:all, анимации размеров, глобального will-change, stagger, пересчёта метрик или покадровых React state updates. Reduced motion отключает CSS motion, сохраняя конечную видимость и текст загрузки.

Backdrop opacity подтверждён на Chromium. Прежний статический blur убран, чтобы затемнение не требовало размытия рабочего пространства. Другие движки не проверялись: если анимация ::backdrop не поддерживается, базовое статическое затемнение сохраняется, lifecycle определяется анимацией самого dialog.

## Автоматические проверки

Все изменяющие данные проверки запускались на новых отдельных БД в `backend/data/motion-<mode>-<timestamp>`. Пароль генерируется для каждого запуска и не записывается в отчёты. Запуск использует реальный контракт BASE_URL, FLAGMAN_DEMO, FLAGMAN_PASSWORD, FLAGMAN_BROWSER. Серверы, браузеры и Vite закрываются после проверки.

| Проверка | Результат |
|---|---|
| `npm run build` из frontend | Успешно: генератор токенов, TypeScript, Vite |
| Полный Playwright-набор на demo-БД | 17 passed, 1 штатный skip onboarding; включая все прежние demo-тесты |
| Финальный `motion.spec.ts`, включая историю и touch | 13 passed; эти две дополнительные проверки добавлены после полного прогона |
| Onboarding на отдельной пустой БД, FLAGMAN_DEMO=false | 1 passed |
| Motion на Vite development / реальном React.StrictMode | 11 passed; до добавления отдельных проверок истории и touch |
| `git diff --check` | Без ошибок содержимого; Git сообщает только штатную конверсию LF/CRLF |

В `frontend/e2e/motion.spec.ts` добавлены проверки 20 циклов диалога, top layer во время выхода, возврата фокуса, игнорирования дочерних/устаревших событий, Combobox Escape, inert списка, быстрого reopen меню, resize через 1024px, передачи фокуса меню → настройки, замены уходящего dialog, отсутствующего CSS-эффекта, выхода из сессии, busy и двойного submit, результата до конца выхода, замены toast и точного нового срока 6500 мс через Playwright clock, SSE без сброса формы/повторного появления раздела, axe, истории партий/поставок/заказов и touch tap.

Обычная production-сборка не выполняет двойной запуск эффектов StrictMode: именно поэтому отдельный прогон `strict` использует Vite dev. В этом режиме прокси сохраняет исходный Host, чтобы не обходить штатную проверку Origin API.

Воспроизводимые команды из корня (локальные SDK и Chromium уже установлены в `.tools`):

```powershell
npm.cmd run build --prefix frontend
node scripts/verify-motion.cjs tests
node scripts/verify-motion.cjs suite
node scripts/verify-motion.cjs onboarding
node scripts/verify-motion.cjs strict
node scripts/verify-motion.cjs after
```

`tests` и `strict` запускают `npx playwright test e2e/motion.spec.ts` через тот же CLI, `suite` — весь набор, эквивалентный `npm run test:e2e`. Дополнительные параметры Playwright можно передавать после mode. Порты разделены: 5096–5103; пользовательский 5080 не затрагивается.

## Визуальная проверка и артефакты

Просмотрены итоговые desktop 1440×960, dialog и mobile 390×844 screenshots, а также выборка кадров из записанного видео: появление и уход диалога, выезд/уход меню, возврат рабочего пространства. Геометрия и текст не масштабируются; подложка плавно меняет opacity; после выхода не остаётся перекрытия. Видео записано headless-браузером, поэтому качество кодирования и масштаб записи не служат проверкой резкости шрифта. Статические screenshots проверены отдельно.

Существующий design E2E проверил все разделы и формы на ширинах 280, 320, 390, 768, 1024, 1440px, горизонтальный overflow, клавиатуру и axe. Отдельная touch-проверка использует hasTouch и настоящие Playwright tap. Reduced motion проверен при открытии и при переключении во время выхода. Полная ручная проверка на физическом телефоне не проводилась.

Артефакты исключены из Git:

- `test-results/motion/after/`: окончательная сборка, JS `index-COfme3KM.js`; те же screenshots/videos/traces/summaries и `animation-metrics-{1,4}.json`.
- `test-results/motion/after/frame-*.png`, `video-contact.png`: кадры 5fps для просмотра записи; меню видно в кадрах 034–035.

Исходная сборка для большого профиля сохранена в игнорируемом `tmp/motion-baseline` через git archive от HEAD до изменений. API остаётся на реальном изолированном сервере. Ранние ошибочные прогоны не использованы в итоговом сравнении.

## Производительность

Windows 10.0.26300; Intel Core i7-9750H @ 2.60GHz, 12 логических ядер, 16 GiB RAM; Node 24.14.0; Chromium 156.0.8078.4, headless. CPU throttling 1× и 4× через CDP. Размеры 1440×960 и 390×844. Одинаковые данные: демо + 10 поставок по 100 партий томатов, всего 1014 партий, 13 поставок, 3 заказа, 1023 движения; snapshot ограничивает партии 500, таблица показывает страницу до 100 строк. Профили записаны последовательно, без параллельного тестового прогона.

Сценарий: 20 открытий/закрытий поставки, открытие/закрытие меню, поиск «томат» по складу (1002 найденных партии). Включены DevTools timeline, user timing и Animation events. React commits отмечены пассивным DevTools hook в тестовом браузере, без изменения приложения; это не отдельная сборка React Profiler с измерением actualDuration.

| CPU | До: Layout / long tasks >50 мс / максимальная long task | После: те же показатели |
|---|---|---|
| 1× | 76 / 2 / 67,6 мс | 113 / 0 / отсутствуют |
| 4× | 76 / 55 / 336,8 мс | 115 / 57 / 347,6 мс |

Layout-события всего сценария включают монтаж форм, изменение inert, смену раздела, поиск, фокус и чтение текущей позиции при прерывании входа. Дополнительные разовые Layout на границах присутствия не являются покадровой интерполяцией.

Во всех 20 завершённых выходных анимациях dialog на обоих throttling внутри интервала (исключая по 20 мс на границах) **0 Layout и 0 React commits**. Входы в быстрых циклах специально прерываются Escape: там присутствуют разовые commits/layout на отмене и переключении фаз. Появление страницы также совпадает с загрузкой snapshot; его события не приписываются покадровому motion-коду. Нет повторяющегося Layout/React commit на каждом кадре выхода. На обычном CPU новые long tasks в записанном сценарии отсутствуют.

При 4× сохраняются long tasks на click/cancel, монтаж/изменение формы, перерасчёт стилей и поиск; итоговое количество 57 против 55. Нельзя объявлять абсолютное отсутствие новых long tasks на замедленном устройстве или гарантировать 60 FPS. В полном сценарии p95 длительности `AnimationFrame` из trace — 15,6 → 10,2 мс при 1× и 111,7 → 95,2 мс при 4×; этот показатель включает тяжёлые открытия/поиск и не равен измеренному FPS дисплея. Одного прогона на режим недостаточно для статистического вывода об ускорении.

После серии: dialogCount=0, body overflow пуст, меню/подложка сняты, E2E подтверждает очистку inert и top layer. Очистка таймеров/слушателей проверена жизненным циклом, повторными действиями и StrictMode. Heap snapshot, отдельный аудит роста GPU-слоёв и длительный тест физического устройства не выполнялись; отсутствие утечки памяти по heap не заявляется.

## Корректировка темпа и прокрутки диалогов

По обратной связи длительности общих переходов увеличены примерно на 20–25%; таблица выше отражает текущие значения. Общий Dialog теперь содержит внутреннюю `.dialog-scroll`, а внешний контур обрезает содержимое по радиусу панели: нативная полоса больше не перекрывает скруглённые углы. Цвета и размер полос прокрутки используют общие дизайн-токены во всём интерфейсе.

Повторная проверка: production build прошёл; `node scripts/verify-motion.cjs tests` — 14 passed; `node scripts/verify-motion.cjs suite --grep 'design:'` — 1 passed. Проверены формы и разделы на ширинах 280/320/390/768/1024/1440, axe и клавиатура. Новый сценарий длинной формы на 390/768/1440 проверяет внутреннюю прокрутку колесом, отсутствие горизонтального overflow, доступность нижней кнопки через фокус и возврат фокуса после Escape. Просмотрены три снимка `test-results/motion/dialog-scroll-{390,768,1440}.png`: скругления симметричны. Браузерные проверки выполнены в Chromium на отдельных демо-БД.

Результаты профилирования выше относятся к первоначальным длительностям; повторное профилирование после этой корректировки не проводилось.
